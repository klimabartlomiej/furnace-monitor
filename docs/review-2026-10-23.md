# Review 2026-10-23 - fix list (v9 on the device)

Found by two independent reviews (firmware, web app) plus checks on the device. All fixes below ship remotely
(no partition change). P1 first.

**Status: fixed in v10 (2026-10-23)**, tested on the device (daily summary rebuilt for 2026-10-22, limits and
settings validation, refill undo by time, app without console errors). Not done, on purpose:
- Eve files are still rewritten every 10 min (LittleFS wear, years) - needs a new Eve storage, later.
- The web upload still sends the OTA password in the query string (LAN-only, plain HTTP anyway).
- Hardware: the counterfeit furnace probe - the user's call.
- Not reproducible without a real fire / a real midnight: stall thresholds, DST day on 2026-10-25 (the code path
  is the same as every midnight, with `tm_isdst = -1`).

## P1 - must

1. **Daily summaries are never stored** - CONFIRMED on the device: `/api/daily` holds one all-zero record instead
   of 2026-10-22. `RingFile::add` (HistoryLog.h) writes mid-file + rewrites the header at offset 0; LittleFS
   copy-on-write needs ~2x the 16-block `daily.bin` while only ~17 of 52 blocks are free. Breaks burn-hour bars,
   week card, coal per day, season, year view; every boot retries the catch-up (up to 31 days, ~1 s each).
   Fix: append-only daily segments (two files, drop the older on rotation, count = size / record). The catch-up
   rebuilds missed days from the minute log (31 days).
2. **DST midnight** - `localMidnight` keeps `tm_isdst` (PiecTemp.ino localMidnight): on 2026-10-25 a 1-hour "day"
   and a record dated 01:00. Fix: `lt.tm_isdst = -1`. Also set TZ in `setup()` (`setenv`+`tzset`), not only in
   `onNetworkUp` - after a soft restart the clock is set before WiFi and days are cut in UTC.
3. **Web: duplicated minutes** - `loadLive` has no in-flight guard; resume (`visibilitychange`) + the 60 s interval
   append the same gap twice -> "Piec pracuje", coal today/week/season doubled, and cached. Fix: single shared
   promise + keep only buckets with `t > last.t`.
4. **Remote update loops** (RemoteUpdate.h) - a rolled-back version is reinstalled every few minutes forever;
   a confirmed version that crashes right after boot never reaches the 2-min check. Fix: skip the version of
   `esp_ota_get_last_invalid_partition()`; after a crash reset check for updates first; `setHandshakeTimeout(10)`.
5. **WiFi fallback hotspot blinds the device** - `processSerialCommand("A")` blocks 15 min then reboots; with the
   router down the ESP records nothing 15 of every 20 min; the hotspot is open. Fix: no automatic hotspot (BOOT
   5 s only), or only when the stored SSID is visible but login fails.
6. **No watchdog, serial can hang** - one stray byte makes HomeSpan wait for a newline forever. Fix:
   `homeSpan.setSerialInputDisable(true)` (field build) + `homeSpan.enableWatchdog(60)`.

## P2 - should

7. Limit typo silently disables the alarm (`parseLimit` -> NAN outside -55..125, client says "zapisano"):
   server 400 + client range check. Same for `handleSettings` numbers silently ignored -> compare reply.
8. Refill "Zapisz"/"Cofnij" double submit (slow reply from `recomputeCoal`): disable buttons; undo by time.
9. Ash / low-coal flap after a power cut before NTP (`known` = true): `known = clockSet(now)` /
   `!isnan(coalLevel)`. Burn-back clears when the hopper probe dies (fire destroys it): keep state while faulty;
   summer mode must not silence burn-back.
10. Stall warning false positives (5 deg at -3/h is normal idling after a controller restart); `stallWatch` never
    cleared -> millis() wrap after 49.7 days. Raise thresholds / clear after the window.
11. Full reset ('F') erases the OTA password -> web upload and IDE OTA accept public `homespan-ota`. Refuse
    uploads and skip `enableOTA()` when no password is stored.
12. Web after an OTA update keeps old JS (banner without notes, old parsers): embed the page's FW version, reload
    when `now.fw` differs. Delete old `furnace-cache-*` keys. Fetch timeouts (AbortController 8 s), no stacked
    refreshes, show data age when stale (cached `now` can be 3 days old with a green dot).
13. Summer mode turns itself on after 2 h of burning - firing the furnace for hot water in summer brings back
    "too cold" alarms afterwards. Longer threshold or ask.
14. `clearHistory` keeps the web cache -> deleted minutes come back for 26 h; reload by polling `/api/now`.

## P3 - later

- Hold timers count `evaluateWarnings()` calls, not minutes (HTTP handlers call it too).
- `RingFile::removeLast` after the 512 ring wraps resurrects the oldest record - zero the slot.
- Low coal estimate gone after 31 days without a full refill (heatSinceFull NAN) - fall back to DayRecord.heat.
- lat/lon accept inf -> invalid `/api/now` JSON forever - range-check.
- Eve files rewritten every 10 min (~2.6k erases/day on 52 blocks) - LittleFS wear in ~3-5 years.
- Minute log can look empty after a cut between sector erase and first record.
- Nothing recorded while WiFi is up but NTP is not (no internet).
- Web: week compares 6 vs 7 days right after midnight (compare averages, reload days when stale); a refill
  time +5 min in the future becomes yesterday (allow +15 min); `loadLive` after a long gap fetches the whole
  gap; days not incremental; outdoor temperature never goes stale.
- Web: contradictions - hot water ignores `now.hotWater` hysteresis; ash/low-coal counted as "alarm" in the
  header; two different 7-day power-cut figures; "z 1 dosypania" after two refills (samples = intervals);
  `dur` can show "1 godz. 60 min".
- Web: 15 s refresh drops the scrub tooltip / tapped bar caption; detail view never slides forward.
- Flash headroom: v9 1,688,576 of 1,769,472 B (79 KB left) - size guard in publish.ps1.
- Hardware: the furnace probe is the counterfeit chip that failed at ~60 C - replace with a genuine DS18B20
  (pin its address in a release) or swap it to the cool coal hopper.
